# ES8311 驱动序列核对 —— 本项目 `src/es8311.c` vs Espressif `esp_codec_dev` 当前版

> 目的（用户选 A）：把 Espressif 官方当前维护的 `esp_codec_dev` 里 ES8311 驱动
> （`espressif/esp-adf` → `components/esp_codec_dev/device/es8311/es8311.c` + `es8311_reg.h`，
> 2026-10-14 抓取 master）与本工程 `src/es8311.c` 的寄存器/初始化/上下电序列逐条比对，
> 产出差异清单。**零代码改动、纯核对**。
>
> 背景：本项目序列是**移植自旧版 esp-adf 的 `es8311.c`**（`.h` 顶部已声明），
> `esp_codec_dev` 是 Espressif 后续演进出的官方组件版，二者是同一颗芯片驱动的
> "旧祖源" 与 "当前版" 关系。本核对的目的就是看旧祖源少了哪些官方后来补的步。

## 1. 初始化序列（`es8311_init` vs `es8311_open`）逐条对比

**本项目 `es8311_init`（src/es8311.c:626）：**
```
0x01=30 0x02=00 0x03=10 0x16=24 0x04=10 0x05=00 0x0B=00 0x0C=00 0x10=1F 0x11=7F
0x00=80(复位)  → 读0x00 &~0x40(从机)
0x01=3F → 读0x01 &~0x80(MCLK来自引脚)
0x02=00 0x05=00 0x03=10 0x04=10 0x08=FF(lrck_l)
0x07=读&0xC0(lrck_h=0)  0x06=读,(v&0xE0)|0x03(bclk_div=4)
0x01=读&~0x40(MCLK不反相)  0x06=读&~0x20(SCK不反相)
0x13=10 0x1B=0A 0x1C=6A 0x44=08
```

**esp_codec_dev `es8311_open`（当前版）：**
```
读0x0D; 若!=0xFA 则写 0x0D=FA            ← (a) 先把芯片置为定义好的掉电态
0x44=08  (噪声免疫)                        ← (b) 双写
0x44=08  (首笔I2C偶发失败→再写一次保可靠)   ← (b)
0x01=30 0x02=00 0x03=10 0x16=24 0x04=10 0x05=00 0x0B=00 0x0C=00 0x10=1F 0x11=7F
0x00=80(复位) → 读0x00 设/清0x40(主从)
0x01=regv(MCLK来源/反相)  0x06=读,设/清0x20(SCK反相)
0x13=10 0x1B=0A 0x1C=6A
0x44=58 (或 no_dac_ref 时 0x08)          ← (c) 打开内部参考 ADCL+DACR
```

**差异：**
| # | 位置 | 本项目 | esp_codec_dev | 风险 |
|---|---|---|---|---|
| D1 | 开头 | 不写 0x0D | 先写 **0x0D=0xFA**（定义好的掉电态） | 低：本项 START 末尾也写 0x0D=0x01 上电，初始化阶段 0x0D 留在复位默认即可 |
| D2 | 0x44 | 写 0x08 **一次** | 写 **0x08 两次**（防首笔 I2C 失败） | 低：本项目的"首笔失败自愈"由 `es8311_write_reg` 的 5 次重试 + bus-clear 层兜底，机制不同但等价 |
| D3 | 结尾 | 0x44=0x08 | 0x44=**0x58**（开内部参考 ADCL+DACR，除非 no_dac_ref） | **中**：本项目只写 0x08。实测仍能出声（故非致命），但 0x58 打开内部参考，可能改善噪声/参考稳定性，建议实测对比 |
| D4 | 时钟分频 | 初始化里直接写 0x08/0x07/0x06（256fs 的两行） | 由 `es8311_config_sample` 的 `coeff_div` 表在 set_fs 时写 | 无功能差：48k 时数值等价 |

## 2. 启动 / DAC 使能序列（`dac_path_regs` vs `es8311_start`）对比

**本项目 `dac_path_regs`（src/es8311.c:731，起播/静音起播共用）：**
```
读0x09 &~0x40(DAC通路开)  读0x0A |0x40(ADC通路关)
0x32=vol  0x17=BF  0x0E=02  0x12=00(上电)  0x14=1A
读0x14 &~0x40(非DMIC)
0x0D=01  0x15=40  0x37=48(ramp)  0x45=00
```

**esp_codec_dev `es8311_start`（当前版）：**
```
0x00=regv(主从)  0x01=regv(MCLK来源/反相)
读0x09/0x0A; dac_iface&=~0x40; adc_iface&=~0x40  (两侧通路都开)
0x09=dac  0x0A=adc
0x17=BF  0x0E=02
(DAC模式) 0x12=00(上电)
0x14=1A  读0x14 设/清0x40(DMIC)  0x0D=01  0x15=40
0x37=08(ramp)  0x45=00
```
上层 `es8311_enable` 的**防爆音顺序**：`es8311_start()` → `pa_power(ENABLE)` → `set_mute(false)`；
禁用时：`set_mute(true)` → `pa_power(DISABLE)` → `suspend()`。

**差异：**
| # | 位置 | 本项目 | esp_codec_dev | 风险 |
|---|---|---|---|---|
| D5 | 0x37 ramp | **0x48**（位[7:4]=4 ⇒ 0.25dB/32LRCK≈0.655ms/0.25dB，慢斜坡） | **0x08**（默认/较快斜坡） | 设计取向不同：本项目靠**硬件慢斜坡 + 音量逐步 ramp**（audio_out.c 8 拍）消爆音；esp_codec_dev 靠 **REG31 静音位** 在上下电瞬间把输出钳到静音、不做慢斜坡。两者都验证可用，**本项目 0x48 是刻意选的**（补丁10 爆音修复） |
| D6 | DAC/ADC 通路 | DAC 开、ADC 关（bit6 处理相反） | 两侧都开，再按 codec_mode 分别清/置 | 低：本项目只播 DAC，关 ADC 更省电，无副作用 |
| D7 | 防爆音机制 | 无 REG31 专用静音位，用 REG32=0（音量最小）静音 | **用 REG31(0x31) 的 0x60 掩码做专用静音** | 中/信息：esp_codec_dev 的"官方防爆音"是 REG31 静音位；本项目从不碰 0x31。本项目靠 0x37=0x48+音量 ramp 也已消爆音，但 REG31 是更"正统"的静音手段，可作备选 |

## 3. 暂停 / 静音机制对比

| 机制 | 本项目 `es8311_dac_mute`（src/es8311.c:783） | esp_codec_dev `es8311_set_mute` |
|---|---|---|
| 静音寄存器 | **REG32 = 0x00**（音量→ -95.5dB，等效静音） | **REG31(0x31)**：`regv & 0x9F`，静音时 `|= 0x60` |
| 是否碰电源/通路 | 只写 1 笔 REG32，芯片保持通电与通路就绪 | 只改 REG31，同样保持芯片通电 |
| 配套淡出 | 由 audio_out.c 在写 REG32=0 后延 12 拍（硬件软斜坡落静音）再停 I2S | 由上层在 mute 前后控制 PA 与时钟 |

> 结论：两者"暂停=静音但不掉电"的思路一致；区别只在静音落在 **REG32（音量）** 还是 **REG31（专用静音位）**。本项目写法有效（板上 4/4 验收），但 REG31 是官方推荐位，未来若要进一步降爆音可评估改走 REG31。

## 4. 停止 / 掉电（挂起）序列（`es8311_stop_dac` vs `es8311_suspend`）对比

**本项目 `es8311_stop_dac`（src/es8311.c:796）：**
```
0x32=00 0x17=00 0x0E=FF 0x12=02(掉电) 0x14=00 0x0D=FA 0x15=00 0x37=08 0x45=01
```

**esp_codec_dev `es8311_suspend`（当前版）—— 完整有序掉电：**
```
0x32=00 0x17=00 0x0E=FF 0x12=02(掉电) 0x14=00 0x0D=FA 0x15=00
0x02=10            ← 时钟分频
0x00=00(复位) 0x00=1F 0x01=30 0x01=00   ← 复位 + 时钟管理归位
0x45=00            ← GP 控制
0x0D=FC            ← 末步再掉电
0x02=00
```

**差异（本项目 stop 明显比官方"薄"）：**
| # | 位置 | 本项目 | esp_codec_dev | 风险 |
|---|---|---|---|---|
| D8 | REG45 | **0x45=0x01** | **0x45=0x00** | **中**：停止时本项目把 GP 控制置 1，官方保持 0。方向相反，建议查 0x45 位定义确认本项目 0x01 的意图（旧祖源遗留？） |
| D9 | 复位/时钟归位 | 无 | 有 0x00=00/1F、0x01=30/00、0x02=10→00 | **中**：官方掉电更彻底（复位数字核 + 时钟管理归位），本项目停在"半掉电"态。下次起播靠 START 重新配，实测可用，但官方序列更干净、掉电态更确定 |
| D10 | 末步 | 0x0D=0xFA 即止 | 末步追加 **0x0D=0xFC** | **低**：官方末步再写一次 0x0D，确保全部掉电 |

## 5. 音量曲线对比

| 项目 | 映射 | 说明 |
|---|---|---|
| 本项目 `es8311_volume_reg` | `vol×0xBF/100`；0→0x00，100→0xBF（0dB） | 上限锁 0xBF（0dB），避免 +32dB 削顶失真（适配 5V 小功放），**刻意保守** |
| esp_codec_dev `vol_range` | 0x00=-95.5dB，0xFF=+32dB，按曲线插值 | 全量程，由 `esp_codec_dev_set_out_vol` 的曲线决定 |

> 本项目映射更有针对性（不削顶），**不是缺陷**；esp_codec_dev 更通用。可保留本项目做法。

## 6. I2C 传输层（不属于序列差异，但决定"能否直接照搬官方"）

esp_codec_dev 跑在 ESP-IDF 的 I2C 驱动上（ESP32 板载上拉充足、总线稳），**没有**任何重试 / bus-clear / 熔断 / 回读补写。
本项目在 STM32 上踩出：**内部 ~40kΩ 弱上拉 → 100kHz 首试 NACK 约 30%** + **从机钳 SDA 卡死**，
因此额外加了 `es8311_write_reg` 5 次重试、`es8311_bus_clear`（9 脉冲+STOP）、熔断、`es8311_dac_readback` 补写。
**这一层官方库不提供、也不需要我们替换**——它只管 codec 寄存器语义，MCU/I2C 传输层仍由本项目 HAL 兜底。

## 7. 差异清单总结（按"是否值得吃进本项目"排序）

| 差异 | 风险 | 建议 |
|---|---|---|
| **D3** 缺 0x44=0x58 内部参考 | 中 | 值得实测：加一笔 `0x44=0x58`（no_dac_ref=false 默认），对比噪声/参考稳定性 |
| **D8** 停止时 0x45=0x01 vs 官方 0x00 | 中 | 查 0x45 位定义；若 0x01 是旧祖源遗留且无依据，改回 0x00 |
| **D9** 掉电序列偏薄（缺复位/时钟归位/末步 0x0D=FC） | 中 | 建议补齐官方 `suspend` 的有序掉电尾（尤其下次起播前若走完整 init 可省，但干净掉电总是更稳） |
| **D7** 官方防爆音用 REG31 静音位，本项目用 REG32=0 | 信息 | 当前 0x37=0x48+音量 ramp 已消爆音（板上验收 4/4）；REG31 作备选，不必动 |
| **D5** 0x37=0x48 vs 官方 0x08 | 设计取向 | **保持本项目 0x48**（爆音修复核心），不动 |
| **D1/D2/D4/D6/D10** | 低 | 低优先级，官方更"完备"但本项目实测可用，按需采纳 |
| 音量映射 0xBF 上限 | 无 | **保持**（防削顶），不采纳官方全量程 |

### 一句话结论
本项目序列是 esp_codec_dev **当前版的旧祖源**，缺的主要是官方后来补的
"完整掉电尾（D8/D9）" 和 "内部参考 0x58（D3）"；
而本项目**刻意保留的 0x37=0x48 + 音量上限 0xBF + STM32 I2C 自愈层** 是官方库没有、且对当前硬件必要的，不应回退。
建议优先实测 D3、修正 D8，其余按需采纳——**无需整体替换库**。

## 8. 落地结论与修正（2026-10-14，补丁11）

用户拍板按推荐实施后，本节记录**实际落地**与几处对上面推演的**修正/证实**。

### 8.1 位定义已用权威源证实（上面几节原为推演）
官方 `esp_codec_dev` 只给寄存器地址名、不给位定义。补丁11 引入 Linux 内核
`sound/soc/codecs/es8311.h`（`torvalds/linux`）作位定义权威，证实/修正如下：

| 项 | 上面推演 | 内核位定义（权威） | 结论 |
|---|---|---|---|
| REG00 bit7 | 猜"软复位脉冲" | **`CSM_ON`**（时钟状态机开）；`RST` 是 bits[4:0] | ✏ 修正：`0x80` 是"开 CSM"，不是复位 |
| REG01 | 只知道写 `0x30→0x3F` | bit5=**MCLK_ON**、bit4=**BCLK_ON**、bit3/2=CLKADC/DAC_ON、bit1/0=ANACLKx_ON | ✏ 补全：`0x3F` = 全时钟使能 |
| REG0D bit2 | 只知 `0xFA`/`0xFC` 不同 | **`PDN_VREF`** | ✅ 证实：`0xFC` 才是"连 VREF 一起断"的真·全掉电 |
| REG31 | 只知掩码 `0x60` | bit6/bit5 = `DAC_DSMMUTE`/`DAC_DEMMUTE` | ✅ 证实：官方静音就是置这两个位 |
| REG37 | `0x48` = 慢硬件 ramp | bits[7:4] = `RAMPRATE` | ✅ 证实（本项目刻意保持 0x48，见 D5）|

### 8.2 ⚠ 上面第 4 节漏掉的关键点：D9 必须与"起播恢复"成对
上面第 4 节把 `suspend` 的掉电尾列全了，但**没说官方 `es8311_start()` 开头会重写
`REG00`/`REG01` 把它们恢复**。既然官方是配对的，本项目也必须配对——否则续播会因
"芯片无时钟"而无声（而音量回读 REG32/REG12 照样正常，**只查音量发现不了**）。
⇒ 实际落地时在 `dac_path_regs()` 开头补了 `REG00=0x80` / `REG01=0x3F`，并新增
REG01/02/06 回读诊断（`g_es_rb_clk1/2/6`）+ 验收脚本 `tools/es8311_clk_check.py`。

### 8.3 实际落地清单（补丁11）
- **D3** ✅ 已实施：`es8311_init()` 末步 `0x44=0x58`（开内部参考 ADCL+DACR）。
- **D2** ✅ 顺带实施：init 最前面 `0x44=0x08` ×2（官方"I2C 噪声免疫前置"；本板 I2C 上拉极弱）。
- **D8** ✅ 已实施：`es8311_stop_dac()` 的 `0x45` 改回 `0x00`。
- **D9** ✅ 已实施：补齐完整掉电尾（含 `0x0D=0xFC`）；删除冗余的 `0x37=0x08`。
- **D7** ❌ 未动：仍用 REG32=0 静音（REG31 专用静音位留作备选）。
- **D5** ❌ 刻意保持 `0x37=0x48`（补丁10 爆音修复核心）。
- **音量上限 0xBF** ✅ 保持（防 5 W 功放削顶）。
- **I2C 自愈层** ✅ 保持（官方库没有、本板必需）。

### 8.4 实测补充
- 本项目 `REG06` 终值 = **0x03**（bits[7:5]=0、DIV_BCLK=3 ⇒ bclk_div=4、SCK 不反相），
  与 48k/12.288 MHz 的 `coeff_div` 期望一致（不是"0xE3"）。
- `REG01` 起播后 = **0x3F**（全时钟使能）、`REG02` = **0x00**，`es8311_clk_check.py` 已钉死这两条。
