# 参考固件哈希 —— 用来判断 "CI 编出来的东西 和 板上跑的那份 是不是同一份字节"
#
# 来源（证据链，可复跑）：
#   1. 本机 E:/ymgui-h743 做"干净重建"，得到 ymgui-h743.elf / .bin
#   2. 同一份源码的两次独立构建（不同构建目录）产出**字节完全相同**的 ELF
#      ⇒ 本机构建是自洽可复现的
#   3. 用 tools/verify_board_image.py 把 STM32H743 的 0x08000000 起 1576644 字节
#      全部读回来，与本地 .bin 逐字节比对 ⇒ **完全一致**
#      ⇒ 板上跑的那份，就是这份源码在当前工具链下编出来的东西
#
# 所以下面这两个哈希 = "目前板上正在运行的固件"。
# CI 里每次构建后都会拿新产物和它比对，**不一致就红灯**。
#
# 更新时机（只有这三种情况允许更新，都要在 commit message 里写清为什么）：
#   a. 有意为之的功能改动导致固件内容变化（新版本落成新基准）
#   b. 工具链版本升级（同步改 .github/workflows/firmware-build.yml 里的 TOOLCHAIN_VERSION）
#   c. 构建参数调整（优化等级 / 宏开关）
# 如果是"没人改代码却变红了"，那是工具链或构建环境漂移，要去查环境，不是改这个哈希。
#
# 格式：sha256 + 两个空格 + 文件名（与 sha256sum 输出一致）
